# Holistic UX Audit + Navigation/IA Redesign (One-page Brief)
**Product**: Construction Data Management Platform (for small–mid GCs + trade contractors)  
**Primary focus**: Information architecture (IA) + navigation clarity (global + tool-level), tier-adaptive packaging

---

## Background
The platform helps contractors tame operational chaos by connecting teams and data across project execution, field operations, and project controls/financial workflows.

## Goals (what this work must accomplish)
- Map the **current IA**: document global navigation and each tool’s local navigation and key paths.
- Identify the **top pain points**: structural/usability issues that block findability and task completion tool-by-tool.
- **Unify/consolidate** navigation: reduce duplication, inconsistent labels, and fragmented patterns.
- Define a personalized **Action Center**: a role-aware landing page that auto-filters to show actionable work, alerts, and status by project(s).
- Propose **tier-adaptive navigation**: a scalable nav model that changes by packaging (Small/Med/Large/Enterprise; Essential/Pro/Advanced/Elite) so smaller tiers stay simple while higher tiers remain powerful.

## Personas / roles in scope
- **Project Manager**: dashboards, multi-project charts, centralized workflows
- **Project Control**: costs/dues, job costs, contractor exposure, project financials
- **Company Management**: people + global configuration (cost codes, templates)
- **Foreman**: advanced suite of field management apps
- **Field Worker**: mobile task code-based timecards; geo-aware site notifications
- **Site Supervisor**: safety, quality, materials deliveries; Safety Huddle, Punch List, event logging

## Tool areas in scope (initial inventory; expand during audit)
- **Planning & schedule**: WBS, Grid, Baseline, Gantt/Visual Gantt, Critical Path, Pull Schedule, Progress Updates
- **Financials & controls**: Project Financials, Budget Revisions, SOV, job costs, contractor exposure
- **Coordination**: RFI, Change Orders, Submittals
- **Quality & safety**: Punch List, Safety Huddle, Jobsite Safety
- **Docs**: Visual Documents
- **Reporting**: Reports
- **Company admin**: People, global configs (cost codes, templates), org settings

---

## Approach (audit methodology)
1. **Inventory + IA mapping (current state)**
   - Catalog global nav + tool-level nav patterns and destinations.
   - Produce an IA map showing: global entry points → tool hubs → key pages → critical actions.
2. **Usability + structural findings**
   - Task walkthroughs per persona (2–4 high-frequency flows each).
   - Identify: ambiguous labels, duplication, inconsistent patterns, dead ends, poor project/company scope transitions.
   - Prioritize issues by severity × frequency × persona impact.
3. **Unification & consolidation opportunities**
   - Cluster tools by user jobs/workflows; propose hubs and standardized local nav templates.
   - Recommend naming/labeling improvements (navigation-focused).
4. **Action Center concept (personalized landing)**
   - Define the information model (cards/sections), personalization rules (role, permissions, project scope, status, tier).
   - Produce 1–2 low-fi concepts (desktop + mobile considerations).
5. **Future-state navigation + packaging strategy**
   - Define Essential/Small “simple nav” and Elite/Enterprise “expanded nav” models.
   - Specify adaptation rules: what collapses into hubs, what is hidden/disabled, and how discovery works without overwhelming users.

## Deliverables
- Current-state **IA map + navigation inventory** (tool-by-tool; global + local patterns)
- **Findings report** (prioritized issues with annotated evidence)
- **Opportunities backlog** (unify/consolidate/extend recommendations)
- **Action Center**: content model + example layouts + personalization logic
- Future-state **navigation proposal**: tier-adaptive IA maps + navigation spec (global + local templates)

## Success criteria
- Faster findability for top tasks (reduced time-to-destination in quick tests)
- Reduced “where do I go?” confusion in usability sessions
- Clearer project vs company scope behavior
- Navigation that fits each tier (no enterprise overkill in Essential/Small)

## Inputs needed (from stakeholders)
- Tool availability by tier (Small/Med/Large/Enterprise; Essential/Pro/Advanced/Elite)
- Rough role/permission matrix
- Access to product/staging (or recordings), plus any analytics or support themes
- Known constraints (technical, brand/header layout, must-keep destinations)

## Suggested timeline
**3–4 weeks** total: current-state map → findings → concepts/spec → iteration with stakeholders
